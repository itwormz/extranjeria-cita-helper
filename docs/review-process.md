# Последовательное ревью PR

Greptile автоматически проверяет новый PR. После завершения первого этапа
и обязательных проверок workflow сам запрашивает первое ревью CodeRabbit.
Исправления в PR сами по себе не запускают повторное ревью ни у одного бота.

## CI для документации

Обычные PR и push в `main` классифицируются по изменённым файлам. Для PR
сравнивается весь набор изменений от общей базы, а не только последний коммит.
Облегчённый режим разрешён только для `README*.md` в корне, `CHANGELOG.md`,
`LICENSE`, Markdown и изображений PNG/JPEG/GIF/WebP/SVG внутри `docs/`.
Код, зависимости, workflow, исполняемые примеры и неизвестные пути требуют
обычных проверок. При переименовании учитываются старый и новый пути.

В режиме документации выполняются проверка локальных ссылок/изображений,
базовой разметки Markdown и приватности исходников. Внешние ссылки не
запрашиваются. Тесты приложения и анализ CodeQL не запускаются. Задания
`Tests`, `Analyze (python)` и `Analyze (actions)` остаются успешными с пояснением
режима, поэтому защита ветки и последовательность ревью не требуют исключений.

Смешанный PR, ручной запуск и плановый CodeQL проходят обычные проверки.
Неудачное сравнение Git завершает проверку ошибкой. Правки документации сами
по себе не меняют версию и не выпускают релиз; выпуск привязан к изменению
`.github/release-version` в `main`. PR, меняющий сам механизм CI, не считается
документационным и проходит обычные проверки.

Локально для правок текста достаточно `python3 scripts/check_docs.py` и
проверки приватности. Полный префлайт приложения для них не нужен.

## Проверка исправлений Greptile

Сначала соберите исправления замечаний, проверьте их тестами и отправьте
одним набором. Не перезапускайте Greptile после каждого небольшого патча.
Когда набор готов, по решению автора добавьте в PR комментарий `@greptileai`.
Дождитесь опубликованного ревью. Ссылка **Last reviewed commit** должна
указывать на текущий коммит PR. Реакция 👀 сама по себе этого не подтверждает.
Greptile может обновить своё основное резюме, не создавая новую запись GitHub
Review. Скрипт принимает такое резюме от бота Greptile, если ссылка в его
footer указывает на текущий коммит этого репозитория и Greptile Review
завершился успешно. Открытые замечания по-прежнему блокируют второй этап.

Проверьте новые замечания и закройте обсуждения, исправления которых
подтверждены. Закрытие обсуждения само по себе не заменяет новое ревью.
Оценка 5/5 не требуется. Зелёный Greptile Review сам по себе тоже не
подтверждает отсутствие замечаний: проверяйте опубликованные findings.

## Запуск CodeRabbit

Workflow **Request CodeRabbit review** проверяет, что PR открыт и не черновик,
последнее опубликованное ревью Greptile
относится к текущему коммиту, Greptile больше не запрашивает изменения,
все его обсуждения закрыты, а обязательные проверки завершились успешно.
Затем он добавляет метку `coderabbit-ready`. В `.coderabbit.yaml` она указана
как положительный фильтр `reviews.auto_review.labels`: CodeRabbit поддерживает
такой запуск даже при `enabled: false`. `auto_incremental_review: false`
сохраняет запрет на автоматическое ревью каждого нового коммита.
Workflow только отправляет запрос. Ответ CodeRabbit и результат его ревью
нужно дождаться отдельно; зелёный workflow этого не подтверждает.

Метка должна существовать в репозитории. При первоначальной настройке создайте её:

```sh
gh label create coderabbit-ready --repo itwormz/extranjeria-cita-helper --color 7C5CFF --description "Greptile and required CI passed; request CodeRabbit review"
```

Используется [поддерживаемый CodeRabbit запуск по метке](https://docs.coderabbit.ai/configuration/auto-review#labels),
а не команда из комментария GitHub Actions. Наличие собственного комментария
workflow не подтверждает, что сервис принял запрос.

Проверка готовности запускается при завершении Greptile Review, Tests и CodeQL.
Дополнительно каждые пять минут проверяются открытые PR в основную ветку:
это подхватывает пропущенные события и обсуждения, закрытые после завершения CI.
Расписание GitHub может задерживаться; запуск ровно через пять минут не гарантируется.
Исполняется только код основной ветки, без загрузки или выполнения кода PR.

Пока метка присутствует, автоматизация не отправляет повторных запросов,
в том числе после новых коммитов. Если ревью ещё не опубликовано, в логе
указывается ожидание CodeRabbit. Уже опубликованное ревью тоже предотвращает
повторный автоматический запуск. Старый комментарий со служебной отметкой
`coderabbit-second-stage-requested` больше не подтверждает запуск второго этапа.
Запуски workflow выполняются последовательно. Лимит сервиса или статус Skipped
не считаются успешным ревью. Не добавляйте служебную метку до завершения первого этапа.

Во время перехода между этапами не отправляйте новые коммиты. Если коммит
изменился до запроса CodeRabbit, нужен актуальный первый этап. После начала
второго этапа исправляем замечания CodeRabbit, не возвращаясь к Greptile.

## Повторная проверка CodeRabbit

Соберите исправления, проверьте тестами и отправьте одним набором. Для проверки
изменений с прошлого ревью добавьте `@coderabbitai review` в PR.
Для повторного запроса через метку выберите в Actions **Request CodeRabbit review →
Run workflow**, оставьте ветку `main` и укажите номер PR. После начала второго
этапа кнопка проверяет актуальные обязательные CI, состояние PR и отсутствие
идущего ревью CodeRabbit; нового ревью Greptile она не требует.
При повторном ручном запросе workflow снимает и снова добавляет метку.
После этого проверьте ответ сервиса. Если нужен именно полный проход с нуля,
добавьте `@coderabbitai full review` от своего имени в обсуждение PR.

Автоматизация начинает работать после мержа workflow в `main`. Для PR,
который добавляет её, первый запрос можно выполнить локальным скриптом из подготовленной ветки
после завершения CI и Greptile. Для проверки готовности без изменения меток можно использовать:

```sh
python3 scripts/request_coderabbit_review.py --repo itwormz/extranjeria-cita-helper --pr 34
```

Для добавления метки после успешной проверки добавьте `--request`.
Нужны GitHub CLI `gh` и авторизация с правом изменять метки PR.
Для проверки всех открытых PR используйте `--automatic` вместо `--pr 34`.
Без `--request` оба режима только проверяют готовность; метки и комментарии не изменяются.
В Actions используется штатный `GITHUB_TOKEN` с правом записи PR (`pull-requests: write`).
Также требуется `actions: read`: команда `gh pr checks` читает данные запусков
workflow, даже когда выводятся только имена и результаты проверок.
Обязательные проверки читаются из сводки ветки REST API и активных rulesets.
Административный доступ к настройкам защиты ветки и отдельный PAT не нужны.

Для проверки доступа без отправки запросов ботам выберите **Run workflow**,
укажите PR и включите **dry_run**. Этот режим использует токен только с правами
чтения и проверяет код выбранной ветки workflow. Он позволяет проверить правку
до мержа в `main`. Если API доступны, но PR ещё не готов к ревью, причина
ожидания выводится в логе; метки и комментарии не изменяются.
